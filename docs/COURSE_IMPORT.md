# 个人教务课程导入

在“评课 → 导入教务课程”使用学校统一认证账号密码，或学校绑定手机号的短信验证码登录。登录后选择学期，获取课程并确认导入；“我的课程”支持按学期查看、直接打开评价和预填课程、开课记录及学期后发布评价。

短信由学校认证平台发送，不经过 Resend。账号密码登录需要学校要求的人工图形、算式、滑块或文字点选验证码时，按提示操作；学校要求短信二次验证时继续输入验证码。需要修改密码或其他暂不支持的二次验证时，应先前往学校认证网站完成要求，再重试导入。

## 数据与合并

- 教务适配依据 [CourseList 导出脚本](https://github.com/ChickenPige0n/CourseList/blob/master/suat-course-table-ics.user.js) 的课表读取路径及字段；登录协议依据学校当前公开认证页面实现。[SUAT_Timetable](https://github.com/Lacus1025/SUAT_Timetable) 当前公开仓库没有可直接集成的登录实现。
- 重复上课安排按学期及教学班来源聚合。`lessonCode` 是教学班标识，不作为可靠课程代码。没有课程代码时提供同名候选，由用户明确选择关联或新增；新增课程展示“课程代码待补充”。
- 已有课程资料仅填补空白；已知零学分不会被覆盖。导入不恢复停用课程，不替换管理员维护的课程、教师关联，也不会自动合并身份不明的同名教师。导入来源中的教师名称作为开课资料单独保留。
- 缺失课程确认后立即进入公共课程库，个人选课关联仅本人可见。重复导入不会重复创建同一来源教学班和个人关联；不会自动删除旧课程和评价。
- 目录、开课、来源映射、个人关联和导入批次在事务内提交。用户状态变化、停用课程或匹配冲突会阻止整批提交。

数据库版本为 **11**。迁移新增课程代码及学分缺失标记、开课教师名称快照、`academic_course_sources`、`user_courses`、`academic_import_batches` 和仅保存 HMAC 摘要的短信限流记录。旧数据库按项目现有迁移命令升级。

## 接口

下列路径均以 `/api/me` 开头，需要已登录且状态正常的平台账号。教务登录不替代平台邮箱登录，也不代表平台已验证学籍。

| 方法         | 路径                                       | 行为                                                                             |
| ------------ | ------------------------------------------ | -------------------------------------------------------------------------------- |
| POST         | `/course-imports`                          | 建立临时会话，返回 `id/state/config/expiresAt`                                   |
| GET / DELETE | `/course-imports/:id`                      | 获取会话状态 / 取消并清理                                                        |
| POST         | `/course-imports/:id/captcha`              | 获取人工验证码图片及类型                                                         |
| POST         | `/course-imports/:id/captcha/verify`       | `points: [{x,y}]`，按学校 310×155 坐标提交手动操作结果                           |
| POST         | `/course-imports/:id/sms`                  | `mobile`，发送学校登录短信，返回重发时间                                         |
| POST         | `/course-imports/:id/login`                | `method=password\|sms`、`account`，以及对应的 `password/captcha` 或 `mobileCode` |
| POST         | `/course-imports/:id/second-factor/send`   | 发送学校要求的二次验证短信                                                       |
| POST         | `/course-imports/:id/second-factor/verify` | `code`，完成二次验证                                                             |
| GET          | `/course-imports/:id/semesters`            | 读取可选学期                                                                     |
| POST         | `/course-imports/:id/preview`              | `semesterId`，获取课程及匹配候选，返回 `previewId`                               |
| POST         | `/course-imports/:id/confirm`              | `previewId`，可选 `matches: {来源标识: 课程ID或"new"}`，提交导入                 |
| GET          | `/courses?term=...`                        | 自己的课程、学期及评价信息                                                       |

状态为 `login → second-factor（如需要）→ authenticated → preview`。确认后清理教务会话；同一用户以相同 `previewId` 重试确认可以读取持久化导入回执。会话与预览不能跨平台用户使用。

## 临时会话与运行要求

密码、短信验证码和教务令牌不会落库、进入日志或浏览器持久化存储。上游 Cookie 使用独立 CookieJar，按域名与路径隔离；仅允许 HTTPS 请求学校认证与教务域名。请求设置超时、响应上限和重定向次数上限。

会话在 API 进程内存中保存，闲置三分钟失效，取消、导入完成、退出或注销时清理。关闭页面会尽力取消，异常断网时由服务端过期机制清理。注销立即删除个人选课关联及个人导入回执，公共课程仍保留。生产部署需要 HTTPS，以及 API 主机可访问 `sso.suat-sz.edu.cn` 和 `jw.suat-sz.edu.cn`。多进程部署应对导入会话使用固定进程路由；进程重启需要重新登录教务。

学校短信重发时间由配置读取，并叠加平台账号及手机号摘要的限流。发送失败也会保留短暂冷却，避免重试风暴。

## 验证与真实验收

后端通过注入式教务客户端覆盖状态、权限、短信限制、匹配、事务、去重和评价关联，并用模拟 HTTP 响应验证学校请求签名、密码编码、Cookie 隔离、人工验证和回调协议。

浏览器测试在隔离本地环境显式注入合成教务客户端，覆盖短信登录、错误验证码、密码及图片验证码、短信二次验证、取消、失效、持久化课程和真实业务评价接口。`ACADEMIC_IMPORT_FIXTURE=true` 只用于此环境，正常开发及生产不得设置；生产和非隔离环境设置后会拒绝启动。浏览器测试不发送真实短信。

已对真实学校站点完成无需账号的初始化与图片验证码获取检查。**真实短信投递、账号登录、学期列表及课表字段仍需用户手动验收**：

1. 正常启动项目或隔离手动测试环境，确认没有开启 `ACADEMIC_IMPORT_FIXTURE`。
2. 自行在页面输入学校绑定手机号，获取并填写学校短信验证码，完成登录。
3. 核对当前学期及历史学期，选择一个学期，核对预览中的课程名称、教师和学分。
4. 确认导入，刷新“我的课程”，核对课程与开课记录；验证查看及发布课程评价。
5. 再次导入相同学期，确认没有重复课程和个人关联；退出平台确认临时教务会话失效。

不要把真实密码、短信验证码、教务 Cookie 或包含个人身份资料的完整响应贴入日志、测试文件或提交记录。
